## 一、结论先行

**能，而且成本很低。** 「单独占一行」在布局上是纯 `Row → Column` 的改动，
没有任何技术障碍；真正决定工作量的是第二个问题——「样式参考 EchoMusic」
参考到什么深度：

- **方案一（静态 hero 卡）**：全宽深色渐变卡 + 黑胶装饰，样式复刻 EchoMusic
  的 `radio-hero`，但不显示实时曲目。**约 0.5 人日，无状态改动。**
- **方案二（动态 hero 卡）**：在方案一基础上，卡片显示 FM 当前曲目、黑胶
  随播放旋转。前提是把 FM 页的局部状态提升为全局 Riverpod provider。
  **再加 1–1.5 人日。**

**建议先做方案一。** 理由见 §五。

## 二、现状

### 本项目

`explore_page.dart` 底部的 `_QuickEntries`（探索页搜索框正下方）：

```dart
Row(
  children: [
    Expanded(child: _EntryCard(... 每日推荐 ...)),   // 半宽
    const SizedBox(width: 12),
    Expanded(child: _EntryCard(... 私人 FM ...)),    // 半宽
  ],
)
```

两张卡是同一个 `_EntryCard`（surface 底色、图标 + 标题 + 副标题），
FM 的副标题是「黑胶电台 · 动态歌池」。**FM 在首页的存在感只有半行。**

另外两处 FM 入口（不在本次范围）：
- 「我的」页 `_EntryTile`（`profile_page.dart:198`）——已经是整行列表项，不动。
- 路由 `/fm` 是 `fullscreenDialog: true` 的全屏页，入口改版不影响路由。

### EchoMusic 的待遇

FM 在 EchoMusic 是**侧边栏一级导航项**（`Sidebar.vue`「我的乐库」分组、
pulse 图标），和「我最喜爱」「音乐云盘」平级——它被当作一个**一等目的地**，
不是首页上的一个格子。本项目只有两个底栏 tab（发现 / 我的），
没有侧边栏，所以「提升 FM 地位」最自然的落点就是发现页给它独占一行、
并且视觉上比其它入口重一档。

## 三、EchoMusic 的样式语言（PersonalFm.vue `radio-hero` 拆解）

FM 页首屏是「左卡片 + 右唱片堆」的 hero 结构，视觉要素：

| 要素 | 实现 | 可迁移性 |
| --- | --- | --- |
| **深色渐变方卡** | `linear-gradient(160deg, primary 30% → #0b1620)` + 左上角 radial 高光，圆角 22px，内描边 `inset 1px white/8%`，双层投影 | ✅ 直接照搬。**任何主题下都是深色卡**（primary 混入深藏青），是页面上的刻意对比色块 |
| **模式切换 pill** | 卡片顶部白/14% 半透明胶囊组（红心/小众/速览），激活态 white/22% | ⬜ 我们只有一条轴（口味/风格/探索），入口卡上**不放**切换器，留在 FM 页内 |
| **大标题** | 28px / 800 / 白色、`letter-spacing: -0.04em` | ✅ 「私人 FM」四个字 |
| **副标题** | 当前曲目「歌名 · 歌手」，无曲目时显示模式副标题 | ⬜ 静态版用固定文案（「黑胶电台 · 动态歌池」）；动态版见 §四 |
| **均衡器条** | 10 根 3px 宽白/40% 圆头竖条，高度 8–19px 固定序列 | ✅ 纯装饰，`Row` + 固定高度列表，10 分钟 |
| **播放 / 不喜欢按钮** | 52px primary 圆钮 + 42px white/12% 圆钮 | 入口卡只放一个播放钮（点击 = push `/fm`），不放不喜欢 |
| **黑胶唱片** | 176px 圆盘：`repeating-radial-gradient` 唱纹 + 中心孔，当前盘**压住卡片右缘 88px**（z 在卡片下），播放时旋转 | ✅ Flutter 用 `ClipOval` + CoverBox + 2~3 圈描边圆环即可；「压住边缘」用 `Positioned(right: -24)` + 卡片 `ClipRRect` 裁切 |
| **登录门槛** | `v-if="!isLoggedIn"` 整页替换 | ❌ 我们的 FM 是搜索池，游客可用，入口**不加门槛**（与现状一致） |

## 四、落地方案

### 方案一：静态 hero 卡（推荐先做）

`_QuickEntries` 改为 `Column`：

```
┌────────────────────────────────────────────┐
│  深色渐变卡（全宽，高 ~132）                  │
│  「私人 FM」28px 白粗体                      │   ⚫ ← 黑胶盘（右侧，
│  黑胶电台 · 动态歌池                          │      CoverBox 圆形 +
│  ▁▃▂▅▃▄▂▄▁▃   (▶)                          │      唱纹环，右缘出血）
└────────────────────────────────────────────┘
┌────────────────────────────────────────────┐
│ 📅  9月19日 · 每日推荐   按日轮换 · 点开即听 → │  ← 每日推荐改横排行卡
└────────────────────────────────────────────┘
```

- 新增私有 `_FmHeroCard`（explore_page.dart 内，与现有私有 widget 风格一致）：
  `Material(透明) → Ink(decoration: 深色渐变) → InkWell → Stack[文案列, 黑胶 Positioned]`。
- 深色卡上的文字用 `kugo.onCover` / `kugo.onCoverMuted`——**token 已存在**
  （排行榜卡的深色 scrim 在用，`explore_page.dart:318-325`），可读性有现成保障。
- 渐变色：`primary` 混深藏青（照搬 EchoMusic 配比），写死深色而不是跟随主题——
  这正是 EchoMusic 的做法，卡片本身是页面上的「刻意深色块」。
  ⚠️ 这与之前纠正过的「深色玻璃拟态」不冲突：那次的问题是**全站卡片**擅自变深色玻璃；
  这次是**单张刻意设计**的 hero 卡、有 EchoMusic 原型和排行榜深色 scrim 两个先例。
- 黑胶装饰盘：右侧 `Positioned(right: -24, bottom: -16)` 圆盘出血，
  卡片 `ClipRRect` 裁掉出界部分——复刻「盘压卡片缘」的层次感。
- **不放旋转动画**（理由见 §五坑 1）。
- 每日推荐改成全宽横排行卡（icon 左、双行文字右），高度与 hero 卡视觉衔接。

**改动面**：`explore_page.dart` 一个文件 + 新增 1–2 例 widget 测试（hero 卡可点、
文案正确）。已 grep 确认**现有测试没有任何一例 pump ExplorePage**，回归风险低。
**约 0.5 人日。**

### 方案二：动态 hero 卡（可选，建议缓做）

在方案一基础上，卡片副标题变成「当前 FM 曲目 · 歌手」，黑胶封面换成真实曲目封面。
**前提**：FM 页状态（`_tracks/_disliked/_anchorIndex/_requestToken`）目前是
`PersonalFmPage` 的 `ConsumerStatefulWidget` 局部状态，入口卡拿不到；
必须提升为 `personalFmControllerProvider`（Notifier），页面变薄壳。

- 收益：入口卡「活」了，FM 的存在感从一行文字变成一张会转的唱片。
- 成本：状态提升重构 1–1.5 人日（含把 7 例 FM 测试迁移到 provider 上）。
- 缓做的理由：**迷你播放条已经在实时显示当前曲目**——FM 在播时，用户从
  hero 卡和迷你条看到的信息是重复的；状态重构的收益主要在「未进入 FM 页时
  预告上次曲目」，价值有限。等「FM 状态全局化」有其它需求牵引时（如路线 B
  第 3 步 `_disliked` 落库）顺势一起做，边际成本更低。

## 五、三个坑（实施时注意）

1. **`repeat()` 动画会挂死 pumpAndSettle**。FM 页的黑胶 `_spin..repeat()` 已经
   踩过一次（7 例测试全部超时）。发现页是常驻首屏，将来任何人对它
   `pumpAndSettle` 都会挂——**方案一不放 repeat 动画**；方案二若加旋转，
   必须仅在 FM 实际播放时旋转，且测试里用 `_settle` 式有界 pump。
2. **黑胶盘不要逐行请求封面**。装饰盘用 `CoverBox(seed)` 的本地确定性封面即可
   （排行榜卡同款做法）；方案二若显示真实曲目封面，用 FM provider 里已有的
   数据，不新增 N+1 请求。
3. **每日推荐不能变成孤儿半宽卡**。FM 拿走独占行后，每日推荐若保持 `Expanded`
   半宽会左边挂一张孤卡。必须同步改成全宽横排行卡（§四 方案一已含）。

## 六、工作量汇总

| 项 | 内容 | 估算 |
| --- | --- | --- |
| 方案一 | `_QuickEntries` 重排 + `_FmHeroCard` + 每日推荐横排卡 + 2 例测试 | **0.5 人日** |
| 方案二 | FM 状态提升 provider + 动态文案/封面 + 测试迁移 | +1–1.5 人日（建议缓做） |

### 建议

**先做方案一。** 一句话理由：EchoMusic 给 FM 的「一等入口」待遇，本质是
**位置 + 视觉权重**两件事；方案一用 0.5 人日把两件事都拿到手，
方案二多花一倍钱买到的只是「卡片上重复迷你条 already 显示的信息」。
