# Windows 任务栏封面预览与独立播控横条

本轮基于 main 的 `d91287c` 实施两个独立、默认关闭的功能：任务栏封面预览、任务栏上方的原生播控浮条。不做 Explorer 内嵌挂接，不改变 Android/Linux 的界面或播放实现，不引入新的播放引擎或依赖。

## 使用方式

Windows 设置页的“窗口”分组新增“任务栏封面预览”和“独立播控横条”。两个开关分别保存，原有任务栏进度开关独立保留；升级不会自动打开新功能。

- **封面预览**：鼠标悬停任务栏图标时显示封面与歌曲/歌手，Peek/Alt+Tab 使用同源信息卡；原有四个缩略图按钮继续可用。关闭后恢复系统默认窗口预览。
- **播控横条**：默认在主窗口所在显示器工作区底部、任务栏上方，显示封面、曲名/歌手、上一曲、播放暂停、下一曲、收藏、进度和音量。拖动封面/标题区域可移动，松手保存位置；进度和音量松手才发命令。
- **窗口行为**：工具窗口、不额外显示任务栏图标、不抢鼠标焦点、置顶；主窗口隐藏到托盘时仍可操作横条。相同显示器的前台全屏应用出现时自动隐藏，退出全屏后恢复；点击横条关闭只关闭横条，同时同步设置开关。

第一版使用高对比深色固定皮肤，不以透明材质、随系统主题切换或任务栏内部布局为交付前提。横条没有键盘焦点，也没有完整 UI Automation 控件树，屏幕阅读器和键盘专用操作仍使用主界面或现有系统媒体入口。

## 架构与评估方案的调整

评估推荐借鉴桌面歌词的进程隔离，并明确不复用第二个播放内核。实施时选择更小的原生 Win32 工具窗口：它不运行 Flutter 子引擎，无需跨进程 Socket/会话令牌，只通过现有 `kugo/taskbar` 主引擎 MethodChannel 接收缓存状态、发送白名单命令。

该调整避免桌面歌词历史上的 Windows 多引擎风险和新增 IPC 生命周期成本，但不提供独立进程级崩溃隔离。原生宿主与播放器共享应用进程，不能声称“横条原生崩溃绝不影响播放”；隐藏/关闭窗口和失效命令不会创建、停止或销毁音频内核。

- **Dart 状态**：`DesktopShell` 从现有 `PlayerController`、`likesProvider` 和设置组装快照，读取实时 position notifier；200ms 节流独立于原有任务栏进度开关。所有按钮仍委托主播放器。
- **Dart 封面**：`DesktopMediaArtwork` 先推送 G 图标，再从现有 CoverCache 取得图片；URL/歌曲身份变化都会提高修订号，过时下载、过时解码和退出后结果不能发布。损坏或下载失败保留 G 图标；无封面不下载。
- **像素边界**：解码前检查编码尺寸和 20MiB 输入限制；按最长边 256 缩放，显式释放 ImmutableBuffer、ImageDescriptor、Codec 和 Image。通道只传 rawStraightRgba，不传 URL、凭据或本地文件路径给窗口过程。
- **原生宿主**：`DesktopMediaHost` 缓存有界像素与文本，网络与图片解码不在 WndProc 中执行。原生也验证歌曲身份、修订号、最多 512×512 的像素长度。换歌即清除旧图，合成不透明 BGRA 后绘制文字。
- **DWM 生命周期**：同时管理缩略图与 live preview；请求尺寸限制为 2048×2048。每次创建的 HBITMAP 在 DWM 调用后立刻 DeleteObject，字体/DC/画刷均成对释放；不随每次进度更新使 DWM 失效。启用 DWM 失败会回退并关闭对应设置。
- **任务栏生命周期**：初始化和 Explorer 重建后等待 `TaskbarButtonCreated` 再添加 Thumbar，避免把 Show 当成 Shell 已就绪；恢复窗口仅更新按钮。
- **命令边界**：进度及曲目按钮携带 identityKey，主进程按当前曲目再次检查。seek 必须有已知时长、有限且范围内的值，previous 尊重 canStepBack；音量必须是 0..1 有限数；未知命令拒绝。
- **拖动竞态**：拖动音量时保留本地预览，不被实时位置/音量快照覆盖；音量是全局设置，换歌不取消音量拖动。窗口拖动也不因换歌释放鼠标捕获；只有 seek 是曲目相关的取消对象。
- **位置/DPI**：保存物理坐标，启动/显示器变化夹到现有工作区，响应 WM_DPICHANGED，命中测试按实际窗口尺寸换算。不是跨进程 SetParent，不修改系统任务栏或 Explorer。
- **退出**：先摘除 Dart 事件、使异步封面失效、关闭功能，然后在主 HWND 的 OnDestroy 销毁原生工具窗口。没有额外子进程可残留。

## 验证记录

实现自带 `app/test/desktop_media_test.dart`，覆盖异步串图、URL 换图、无图/坏图、退出竞态、歌曲身份、seek/volume 边界、坐标、开关持久化与通道负载。原生独立探针在 Windows CI 编译并创建真实 HWND，检查 DWM 属性、窗口样式、真实窗口消息、拖进度、全屏隐藏、关闭与重复绘制资源数量；探针不创建音频播放器。

本地静态分析、完整 1,168 项回归、7 项发布打包检查及新增 25 项 Dart 测试均已通过，其中一项真实解码 G 图标资源并验证 256×256 RGBA 通道负载；MinGW 严格交叉编译（C++17、Wall/Wextra/Wconversion/Werror）已通过。Windows MSVC Release 应用与原生探针编译也已通过，最终 CI 原生探针结果将在通过后回填；不能把交叉编译或程序化 DWM 消息当成实际鼠标悬停验收。

首轮探针发现的是验证方法错误：`DWMWA_HAS_ICONIC_BITMAP` 和 `DWMWA_FORCE_ICONIC_REPRESENTATION` 文档指定用于 DwmSetWindowAttribute，不应以 DwmGetWindowAttribute 读取作为“设置成功”判据。探针已改为验证宿主记录的真实设置 HRESULT，并直接检查位图提交 HRESULT。（[Microsoft 属性说明](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)）

第二轮 CI 中缩略图提交返回 S_OK，但全尺寸 Peek 提交返回 `0x80070032 / ERROR_NOT_SUPPORTED`。这只能证明该 CI 调用不支持，不能据此断言具体系统原因或宣称 Peek 验收成功。宿主新增真实失败时取消两项强制预览属性、恢复系统预览、关闭对应设置的降级处理，不影响独立横条。探针只对这个精确错误标记 `SKIP native Peek acceptance`，同时严格检查降级；其他 HRESULT 仍使 CI 失败。缩略图压力与 GDI 资源检查在 Peek 调用之前完成，避免降级后空跑压力测试。原生探针在原有 apps.yml 中独立为早期 Windows job，没有增加第二个工作流。

## 验收边界与后续

仍需使用者设备验证 Windows 10/11 的实际任务栏悬停、Peek/Alt+Tab、固定图标、多显示器 100%/150%/200% 缩放与拖动、自动隐藏任务栏、Explorer 重启、长时间快速切歌、真实在线音源及声音。Windows CI 原生探针不覆盖这些组合，首次发布保留默认关闭。

真正嵌入任务栏、透明主题、完整 UIA/键盘操作、独立进程崩溃隔离不属于本轮完成项。若后续明确要求任务栏内部横条，另建隔离实验，不把外部浮条当成内嵌方案完成。
